## NOC COUNTERFACTUAL — what KPM-1 would have scored with an explicit NOC class

**On the 22 declared councils so far (16% of total):**

| Rule | Accuracy |
|---|---|
| BASELINE — no NOC class (current KPM-1) | 8/22 = **36%** |
| margin < 3pp → NOC | 11/22 = 50% |
| margin < 4pp → NOC | 12/22 = 55% |
| margin < 5pp → NOC | 12/22 = 55% |
| **margin < 7pp → NOC** | **14/22 = 64%** ← **OPTIMAL** |
| margin < 8pp → NOC | 14/22 = 64% |
| margin < 10pp → NOC | 13/22 = 59% |

**Headline finding for the methodology paper:**

> Adding a single rule — "if predicted winner-runner-up margin < 7pp, output No overall control" — would have moved KPM-1 from 36% to 64% accuracy on the 22 declared councils. The persona panel's vote-share predictions are not the failure point; the absence of an explicit NOC class in the post-processor is.

This number is the cleanest proof point for the central framing line: *"The persona panel was the right architecture. The control classifier was the wrong post-processor."*

Caveat: 22 of 136 is 16% of the sample; rerun this analysis on the full count Saturday. The 7pp threshold is the optimum on this sub-sample but may shift slightly with metro/county data.

PollCheck (88% on 16 declared) still beats this. Their NOC heuristic appears more aggressive than 7pp-margin alone — likely uses additional signals (probability-of-control bootstrap or similar). But the gap closes from 57pp to 24pp with the single-rule fix.
